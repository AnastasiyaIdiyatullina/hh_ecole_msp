# Автообновление фида МШП для HH

Скрипт `build_feed.py` раз в 6 часов заходит на страницы курсов, берёт актуальные
цену и старую цену, пересчитывает скидку и ежемесячный платёж и обновляет `docs/feed.xml`.
Список курсов и ссылки берутся из самого фида, поэтому новый курс добавляется копированием
блока `<offer>` в `docs/feed.xml`.

## Запуск

1. Создайте репозиторий на GitHub и залейте в него содержимое этой папки.
2. Settings -> Pages -> Source: `Deploy from a branch`, ветка `main`, папка `/docs`.
3. Settings -> Actions -> General -> Workflow permissions -> `Read and write permissions`.
4. Вкладка Actions -> `Update HH feed` -> `Run workflow` (первый ручной прогон).
5. Ссылка на фид для HH: `https://<логин>.github.io/<репозиторий>/feed.xml`.

## Первая настройка парсера (важно)

Структуру страниц курсов на момент написания проверить не удалось, поэтому перед
боевым запуском прогоните скрипт локально:

    pip install -r requirements.txt
    python build_feed.py --dry-run --debug

В выводе по каждому курсу видно, какие числа найдены на странице и какая пара
«старая цена / цена» выбрана. Если на всех страницах пара найдена, всё работает.
Если пишет «цены не найдены», скорее всего, цены дорисовываются JavaScript-ом
(не видны в исходном HTML). Тогда нужен другой источник: JSON-эндпоинт, который
дёргает страница (смотрите вкладку Network в DevTools), или выгрузка из CRM.

## Как скрипт защищает фид

- fetch идёт без utm-меток, чтобы не засорять аналитику фиктивными визитами;
- пара цен подтверждается прежней скидкой или прежней ценой, случайные числа на странице игнорируются;
- если цена изменилась больше чем на 50% за один прогон, оффер не трогается, в логе предупреждение;
- если успешно обработано меньше 70% страниц, фид не перезаписывается, workflow падает
  и GitHub присылает письмо;
- дата `yml_catalog` обновляется только когда цены реально изменились.

## Что скрипт не меняет

Промокоды, названия, описания, длительность, ссылки, `available`. Если курс снят с продажи,
поставьте `available="false"` вручную.

## Ограничения GitHub

Если в репозитории нет активности 60 дней, GitHub отключает расписание. Пока цены меняются
и бот коммитит, этого не произойдёт; если долго без изменений, включите workflow заново.
